# DSR — FB2 Accent Converter
[![Версия](https://img.shields.io/badge/version-1.7.6-blue)](https://github.com/dejik1983-crypto/DSR/releases)

**Версия: 1.7.6** · [История изменений](CHANGELOG.md) · [Лицензия MIT](LICENSE)

Готовый файл называется `DSR.exe`, и для переноса на другой компьютер достаточно только его: словари и необязательный движок add-stress уже встроены. Всё, что программа скачивает или создаёт при первом запуске (окружение Python, скрипты, кэши, модели), хранится в папке `ресурсы` рядом с `DSR.exe`; размер ресурсов отображается в окне программы. Папку можно удалить целиком — программа восстановит встроенные словари из exe и скачает остальное заново.

DSR создаёт копии FB2-книг с автоматически расставленными русскими ударениями. Ударения записываются комбинируемым символом `U+0301`, который распознаёт и корректно отображает [DeepReader](https://github.com/dejik1983-crypto/DeepReader).

> Автоматическая расстановка может ошибаться, особенно на омографах, стихах и специальных текстах. Проверяйте результат перед использованием. DSR по умолчанию сохраняет отдельную копию и не изменяет исходную книгу.

Для разбора и проверки FB2 используется встроенный парсер `Fb2Parser` (перенесён в папку `Parser` этого проекта), поэтому отдельный проект DeepReader для сборки не нужен. После обработки результат проверяется тем же парсером. Преобразуются текстовые узлы XML, а встроенные изображения не передаются языковой модели.

**Сторонние компоненты:** расстановка ударений выполняется библиотекой [RUAccent](https://github.com/Den4ikAI/ruaccent), которая имеет собственную лицензию и зависимости. Перед распространением готовой сборки ознакомьтесь с их условиями.

## Возможности
- Один запуск — два движка: исходная книга автоматически проходит через RUAccent, затем
  через Silero, после чего результаты сравниваются, а расхождения собираются в отдельный отчёт.
- Обработка целой книги FB2 или всего текстового файла TXT.
- Выбор модели RUAccent и устройства CPU/CUDA.
- Исходник никогда не перезаписывается: всё производное (прогоны движков, отчёты, словоформы,
  итог) складывается рядом в папку `DSR_<имя книги>`.
- Сохранение иллюстраций либо их исключение из выходной копии.
- Ручная доводка ударений и опечаток с сохранением итогового файла.
- CLI для пакетной обработки.
- Проверка результата встроенным парсером FB2.

## Требования
- Windows x64.
- Доступ к интернету при первом запуске. Python устанавливать не обязательно: если на компьютере нет Python 3.10+, DSR скачает переносимый CPython в `ресурсы\python-base` и создаст окружение сам.
- Инференс моделей ударений выполняется ONNX Runtime. Для ускорения на NVIDIA RTX нужны актуальный драйвер и `onnxruntime-gpu` с подходящим CUDA/cuDNN runtime. Дополнительная опциональная rule-модель RUAccent отключена; используются нейросетевые модели.
- Движки подсказок на PyTorch (silero-stress, omogre) используют свою сборку PyTorch: по умолчанию для процессора, а с CUDA — по кнопке во второй вкладке (нужны драйвер NVIDIA и около трёх гигабайт свободного места).
- При первом запуске выбранная RUAccent-модель скачивается из интернета.
- Для сборки из исходников нужны Windows и .NET 8 SDK: внешний проект DeepReader больше не требуется.

## Сборка и установка
Чтобы собрать приложение из исходников, необходимы Windows и .NET 8 SDK. Парсер FB2 (`Fb2Parser`) входит в проект в папке `Parser`, поэтому подключать соседние проекты не нужно.

Для публикации приложения выполните из папки DSR:

```powershell
.\publish.bat
```

Каталог `publish` содержит только `DSR.exe`. Исполняемый файл включает .NET runtime, встроенный парсер FB2, словари, движок add-stress, воркеры Python и скрипты; дополнительные модели и Python-зависимости устанавливаются при запуске по запросу.

Все создаваемые при работе ресурсы находятся рядом с `DSR.exe` в папке `ресурсы`:

```text
ресурсы\
├── python\               окружение Python и установленные библиотеки
├── python-base\          переносимый Python (только если его не было в системе)
├── dictionary\           словари, распакованные из DSR.exe
├── add-stress\           библиотека add-stress и модель spaCy из DSR.exe (зависимости ставятся при первом запуске)
├── модели\               модели RUAccent и Hugging Face
├── кэш\                  кэш установщика pip и прочие кэши
├── временные-файлы\      временные данные загрузки и обработки
└── *.py                  воркеры, извлекаемые из DSR.exe
```

Окно программы показывает суммарный объём ресурсов и разбивку по категориям. Для записи рядом с `DSR.exe` у пользователя должны быть права; не размещайте приложение в защищённой папке вроде `Program Files`.

При первом запуске в новом месте DSR предупреждает, что скачает Python-окружение и модель, и показывает прогресс. На целевом компьютере нужен только интернет: если Python 3.10+ не найден, DSR скачает переносимый CPython и создаст окружение сам. Можно указать свой Python переменной среды `PYTHON`. Повторно готовить окружение не нужно: при следующих запусках DSR проверяет отметку `ресурсы\.dsr-подготовлено.json` и файлы модели.

Пересоздать окружение можно кнопками «Очистить всё» и «Загрузить ресурсы заново» либо проверить его без окна:

```powershell
.\DSR.exe --check-resources
```

Если обнаружена NVIDIA RTX, но CUDA-провайдер не установлен, нажмите «Проверить GPU» и подтвердите установку. DSR установит в локальное окружение `ресурсы\python` официальный GPU-пакет ONNX Runtime с extras `[cuda,cudnn]` (вместе с CUDA/cuDNN runtime DLL) и повторит проверку. Этот механизм соответствует [официальным инструкциям ONNX Runtime для CUDA](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html). Для работы GPU также нужны актуальный драйвер NVIDIA и подходящая версия runtime.

```powershell
& ".\ресурсы\python\Scripts\python.exe" -m pip uninstall -y onnxruntime
& ".\ресурсы\python\Scripts\python.exe" -m pip install onnxruntime-gpu
```

Обратите внимание: пакет `onnxruntime-gpu` должен быть собран под установленную версию CUDA. Если установить `onnxruntime-gpu`, собранный под другую версию CUDA, ONNX Runtime предупредит об этом и не включит CUDA — в таком случае подберите сборку под вашу CUDA или обновите CUDA/cuDNN runtime. Пакеты PyTorch не управляют вычислениями RUAccent. После установки перезапустите DSR. Кнопка «Проверить GPU» проверяет наличие NVIDIA RTX и CUDA Execution Provider ONNX Runtime. Затем при загрузке RUAccent проверяется, что модели действительно зарегистрировали CUDA provider; иначе запуск CUDA завершится ясной ошибкой. Если проверка GPU не пройдена, приложение оставит CPU.

## Использование
### Графический интерфейс
Запустите `DSR.exe` без аргументов — откроется графический интерфейс из трёх шагов.

**1. Обработка книги.** Выберите файл FB2 или TXT и нажмите «Обработать книгу»: DSR сначала
прогонит книгу через RUAccent, затем (если включена галочка «Второе мнение») через Silero и
сравнит оба результата. Модель RUAccent и устройство CPU/CUDA можно не трогать — они
подбираются сами; окружение Python готовится автоматически при первом запуске, в новом месте,
на новом компьютере и после смены модели. Для FB2 можно оставить включённым сохранение
иллюстраций. Рабочая папка `DSR_<имя книги>` и пути результата подставляются сами.

Внутри рабочей папки рядом с исходником появляются:

```text
DSR_<имя книги>\
├── RUAccent\
│   ├── <имя>_ruaccent.<fb2|txt>            книга с ударениями RUAccent
│   ├── <имя>_ruaccent_статистика.txt       отчёт прогона RUAccent
│   └── <имя>_ruaccent_нераспознанные.txt   слова без ударения
├── Silero\
│   ├── <имя>_silero.<fb2|txt>              отдельный прогон Silero
│   ├── <имя>_silero_статистика.txt         отчёт прогона Silero
│   └── <имя>_silero_нераспознанные.txt     слова без ударения
├── <имя>_расхождения.txt                   сводка: расхождения и нераспознанные слова
├── <имя>_расхождения_статистика.txt        статистика сравнения (три категории)
├── <имя>_словоформы.json                   сохранённые словоформы и правки
└── <имя>_итог.<fb2|txt>                     итог после ручной доводки
```

Исходная книга не изменяется; в любой момент прогоны и отчёты можно пересоздать.

**2. Расхождения и ИИ** (можно пропустить). Сводка делит все многосложные слова на три
категории: ударение совпало (слово проходит и в отчёт не попадает), расхождение (модели поставили
ударение на разные гласные или одна модель промолчала, а вторая поставила) и «не распознали обе
модели». В списке вкладки — расхождения; слова без ударения у обеих моделей видны в сводке
(`<имя>_расхождения.txt`, раздел «Категория 3») и в ручной доводке. Выберите движок подсказок
(**omogre** — локальная контекстная модель омографов, лучше всего разбирает спорные случаи; своя
модель на диске, Ollama или внешний API) и нажмите «Подсказки ИИ по расхождениям». Найденное — только
подсказки: где ИИ не уверен, слово уходит в ручную доводку без варианта. Кнопка «Подсказки ИИ»
спрашивает движок только по новым словам, а «Перепроверить с помощью ИИ» — заново по всем словам отчёта.

Движок **omogre** работает на этом же компьютере и выбирает ударение по предложению, а не по слову
в отрыве от него, поэтому именно он уверенно разводит омографы (`за́мок`/`замо́к`, `сто́ит`/`стои́т`,
`му́ку`/`мука́`, `все`/`всё`). Он разбирает **каждый случай расхождения отдельно**: на одно и то же
слово в разных предложениях может прийти разное ударение. После прохода результат виден на вкладке
«3. Контроль ИИ результатов». При первом выборе omogre сам ставит библиотеку и PyTorch (CPU) и
скачивает модель около 120 МБ в `ресурсы\модели\omogre`; дальше работает без интернета. Кнопка
«Проверить движок» прогоняет по нему контрольные слова и показывает точность и скорость.

Движок считает на процессоре, а счёт можно увести на видеокарту NVIDIA. PyTorch ставится сразу
сборкой для процессора — она вчетверо легче. Сборка с CUDA ставится отдельным шагом в окне движка
(кнопка «Поставить сборку с CUDA», около трёх гигабайт, установка заняла около пяти минут) и снимает
с процессора самую долгую часть — счёт сети. Нажимать её можно и до первого запуска omogre: если
PyTorch ещё не стоит, DSR сначала поставит лёгкую CPU-сборку, узнает её версию и затем скачает
CUDA-сборку. Ответы при этом не меняются: разбор всех 4362 случаев
«Тихого Дона. Тома 1» на RTX 3060 Ti занимает 6,9 с против 26 с на процессоре, и ответы совпадают
до последнего (4230 из 4230). Выбор «процессор или видеокарта» сохраняется в
`ресурсы\настройки-окна.json` и действует на оба движка подсказок — silero-stress и omogre. Если
сборки с CUDA нет или карта не отвечает, движок считает на процессоре и говорит об этом в строке хода
работы. Из командной строки то же самое делают ключи `--torch-status`, `--torch-cuda`, `--torch-cpu` и
`--llm-device CPU|CUDA`.

Часть узкого места — не счёт, а число обращений к сети. Внутри omogre есть вторая модель — для слов,
которых нет в словаре ударений, — и библиотека зовёт её по одному слову без контекста; на таких
входах время уходит на запуск сети, а не на счёт. Поэтому ускорены сами вызовы: такие слова
считаются пачками и запоминаются на весь сеанс. На книге объёмом с «Тихий Дон. Том 1» разбор
4362 случаев занимает около 30 с вместо 203 с, ответы при этом те же.

Для внешнего API (например, OpenRouter: адрес `https://openrouter.ai/api/v1`) адрес, ключ и модель
задаются в окне движка. Бесплатные модели на OpenRouter дают 50 запросов в сутки на ключ без
средств; если лимит исчерпан, проход сразу сообщает причину, а не повторяет запрос с паузами.

**3. Контроль ИИ результатов.** Появляется после прохода omogre. Сверху — слово, ниже три окна:
слева вариант 1 (общая форма группы, её модель выбрала чаще), справа вариант 2 (случаи, которым
омогре дал другое ударение по контексту), третье — ударение на предлог («на́ пол», «на́ ноги»).
В каждом окне — конкретные вхождения слова с той фразой, в которой оно стоит, и своим ударением.
Один щелчок по случаю раскрывает фрагмент целиком для
чтения — проверяемое слово подсвечено так же, как в ручной доводке; повторный щелчок сворачивает
фразу обратно. Раскрыт всегда один случай: прежний сворачивается и помечается прочитанным — слева
у него появляется полоска, а в заголовке окна видно, сколько случаев уже прочитано. Двойной щелчок
переносит случай в другое окно (у этого вхождения будет «своя форма» второго варианта) — как и
перетаскивание мышкой, и кнопки «← →». Правая кнопка мыши открывает такое же меню, как в ручной
доводке: «Копировать слово и контекст», «Открыть предложение в Google: куда поставить ударение?» и
перенос случая. Кнопки «◀ Слово / Слово ▶» листают слова, «Отменить перенос» возвращает последний
перенос и умеет отменять по шагам назад, а «Журнал правок» показывает все переносы и отмены со
временем, словом и фрагментом (двойной щелчок по строке возвращает к этому случаю) и сохраняет их
в txt-документ рядом с отчётом. «Сохранить контроль» записывает результат в отчёт, «Перейти к
ручной доводке →» открывает следующую вкладку, показывает там это слово с выбранным случаем и
убирает слово из списков расхождений и контроля ИИ. Если слово скрывал фильтр или выключенный
показ проверенных, DSR снимает этот фильтр, чтобы перенесённое слово было видно. Вернуть его можно
перетаскиванием обратно на заголовок вкладки 3.
Третье окно — для случаев, где ударение уходит на предлог: «на́ пол», «по́ полу», «на́ ноги». Разбор
энклиноменов сам находит известные сочетания; если слова нет в списке, случай всё равно можно
перенести кнопкой «⇢», перетаскиванием или через меню — DSR поставит знак на предлог и пометит
случай вопросом, потому что перенос выбран вручную и его надо проверить глазами. «⇠» возвращает
случай из третьего окна в вариант 1.
В заголовке каждого окна видно, сколько его случаев поддержали RUAccent и Silero, а у варианта,
который ИИ считала общей формой слова, стоит зелёная метка «✔ выбор ИИ»; перенесённые случаи
помечены «✗» — с подсказкой, что предлагала ИИ. «Сбросить прочитанное» убирает пометки, чтобы
пройти слово заново (переносы при этом остаются). Статистика точности считается по проверенным
случаям: сколько раз ИИ была права, сколько ошиблась и как часто с вашим решением совпадали
RUAccent и Silero. Кнопка «Отчёт о точности» показывает процент на себе и пишет рядом с отчётом
`<отчёт>_точность-ии.txt` — итог, разбор по словам и списки случаев, где ИИ права и где ошиблась.
Проверенные случаи уходят в журнал примеров `ресурсы\накопленные-примеры.jsonl` для будущего
обучения моделей, а ответы ИИ по каждому вхождению хранятся в `ресурсы\ии-по-случаям.json`.
Словоформы без расхождения по случаям здесь не показываются: у них один вариант на слово, и
разносить по окнам нечего.

**4. Ручная доводка.** Выберите слово в списке слева, поставьте ударение кнопкой гласной или
исправьте опечатку прямо в поле «Фрагмент текста» и нажмите «Да ✓» (кнопка наверху, справа от
«УНИК»). Галочки в списке контекстов разделяют случаи одного слова: отмеченные образцы берут общую
форму — ударение, набранное на любом из них, идёт по всей отмеченной части; у снятого образца своё
ударение, оно ставится только в этом месте текста (например «за́мок» — строение и «замо́к» — запор
в одной книге). Снятые образцы помечены пометкой «своя форма». Список «Показывать» фильтрует слова
по готовности подсказки ИИ (все расхождения / ИИ предложил вариант / ИИ не уверен); над редактором
видна плашка с вердиктом ИИ по выбранному слову. В конце нажмите «Применить всё и сохранить» — итог
соберётся в `<имя>_итог.<fb2|txt>` внутри рабочей папки. Для редких слов, где ударная не гласная
(`свѣ́тлостію`, `мѣ́дъ`), справа от «Ударение в слове» есть кнопка **УНИК**: она открывает панель,
где ударение ставится кликом по любой букве слова.

Отчёт расхождений при этом не теряется: все слова остаются в файле, а у проверенных появляется
строка `Проверено [слово]: <дата и время>`. В списках они помечены галочкой и скрыты; галочка
«Показывать проверенные» возвращает их, чтобы решение можно было изменить. К документу можно
вернуться кнопкой «Продолжить: <документ>» — DSR подставит отчёт и итоговый файл.

Кнопка «Очистить всё» удаляет папку `ресурсы` рядом с приложением. Файл `DSR.exe` и ваши книги
не затрагиваются; после этого ресурсы можно установить повторно. «Проверить ресурсы» показывает,
что на месте (словари, окружение, модель), ничего не скачивая, а «Загрузить ресурсы заново»
удаляет папку и готовит всё с прогрессом.

Подсказок в интерфейсе много — у каждой кнопки и поля есть пояснение. Если они мешают, поставьте
галочку «Выключить всплывающие подсказки» в шапке окна: она убирает все сразу, и выбор сохраняется
в `ресурсы\настройки-окна.json`, то есть действует и при следующем запуске.

### Командная строка
Для пакетной обработки и автоматизации доступен CLI. Полный список параметров: `DSR.exe --help`.

```powershell
.\DSR.exe "D:\Books\Книга.fb2" --model turbo3.1 --device CPU
```

Для пакетного режима можно передать папку; для рекурсивного обхода добавьте `--recursive`. При ошибке временный файл результата удаляется, исходник остаётся нетронутым.

## Сборка из исходников
DSR — самостоятельный проект: парсер FB2 уже входит в него, клонировать и подключать рядом другие проекты не нужно.

```text
<workspace>/
└── DSR/
```

Соберите релизную версию из папки DSR:

```powershell
.\publish.bat
```

Скрипт `publish.bat` (и его аналог `install.bat`) собирает один файл `DSR.exe` в `DSR/publish/`; Python-окружение устанавливается не на этапе сборки, а при первом запуске программы на целевом компьютере.

## RUAccent
Используется библиотека [RUAccent](https://github.com/Den4ikAI/ruaccent). Символ `+` перед ударной гласной в ответе модели преобразуется в комбинируемое ударение `U+0301`, поддерживаемое DeepReader. Результаты модели могут быть неточными — всегда проверяйте обработанный текст.
